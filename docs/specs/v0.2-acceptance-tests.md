# v0.2 acceptance tests

Every acceptance item references the behavior specification. Tests are written
before the implementation they require. A red test commit must precede its
corresponding feature commit.

## 1. Specification and traceability

- **AT-SPEC-01** The three v0.2 specification documents exist before any v0.2
  implementation commit.
- **AT-SPEC-02** Each new test names the relevant acceptance or behavior ID in
  its docstring, test name, or adjacent comment.
- **AT-SPEC-03** The final status maps every acceptance item to implemented and
  tested, locally tested only, scaffold only, or not implemented.

## 2. Model backend

- **AT-MB-01** A fake backend satisfies the minimal `ModelBackend` protocol
  without Qwen-specific fields.
- **AT-MB-02** Candidate query invokes `score_allowed_tokens` but never
  `update_context`, `_forward_tokens`, or `model.forward`.
- **AT-MB-03** Full-logits scoring returns exact selected entries from an
  immutable CPU score vector.
- **AT-MB-04** Sparse projection over deterministic fake tensors matches full
  projection top-1, top-k set, and scores within `1e-4`.
- **AT-MB-05** Real GPU benchmark, when explicitly enabled, records allowed
  token counts, projection/query latency, peak allocated bytes, and publication
  latency for both backends. Absence of the target GPU is a reported skip, not a
  fabricated result.
- **AT-MB-06** Backend diagnostics identify backend kind and state epoch.
- **AT-MB-07** Private-state invalidation makes every older state unqueryable.

## 3. Unified candidates and script policy

- **AT-CN-01** With context `该协议所消耗的` and keys `jiuchan`, the deterministic
  acceptance fixture ranks `纠缠` first.
- **AT-CN-02** With context `这个模型使用` and keys `qwen`, at least one Latin
  candidate is allowed.
- **AT-EN-01** With context
  `The receiver-centred placement is operationally` and keys `asy`, candidates
  include `asymmetric`.
- **AT-EN-02** The same English query publishes zero candidates containing Han
  characters.
- **AT-EN-03** With context `The protocol is` and keys `non`, literal `non`
  remains commit-able even if the model returns no completion.
- **AT-EN-04** Latin search accepts a candidate split across multiple tokens.
- **AT-EN-05** Latin search supports case, internal hyphen, and apostrophe.
- **AT-EN-06** Deleting and retyping a prefix produces a result based only on
  current keys.
- **AT-UC-01** Pinyin and Latin candidates are instances of the same candidate
  type and use the same deduplication/ranking function.
- **AT-UC-02** Every published candidate contains all unified score, script,
  epoch, and token-path fields.
- **AT-SP-01** English-dominant context hard rejects every Han candidate,
  regardless of model score.
- **AT-SP-02** Chinese-dominant context allows Han and does not globally forbid
  Latin.
- **AT-SP-03** Empty/no context has deterministic Chinese-weak-default behavior
  while allowing literal Latin.
- **AT-SP-04** An explicit uppercase/acronym/non-pinyin shape can remove the
  modest Chinese-context Latin penalty without a name whitelist.

## 4. Realtime and epoch behavior

- **AT-RT-01** A spy model proves candidate query never calls
  `model.forward`/`update_context`.
- **AT-RT-02** While epoch `n+1` is refreshing, a new key can query immutable
  epoch `n`.
- **AT-RT-03** A stale epoch response cannot overwrite a newer requested or
  published epoch.
- **AT-RT-04** Snapshot age is present in diagnostics and may exceed 100 ms
  without rejecting a query.
- **AT-RT-05** Service unavailable returns a safe no-replacement/literal result
  within the configured test deadline.
- **AT-RT-06** Query results with mismatched session, revision, or epoch are
  discarded by the native boundary.

## 5. Key state machine

- **AT-KS-01** In English mode, `Space` commits the literal typed prefix plus
  one space, never the offered completion.
- **AT-KS-02** In English mode, `Tab` accepts the selected completion.
- **AT-KS-03** In English mode, `Escape` dismisses completion without replacing
  the literal prefix.
- **AT-KS-04** In Chinese mode, `Space` and number keys commit the selected
  pinyin candidate.
- **AT-KS-05** `Enter` preserves the specified literal behavior in both modes.
- **AT-KS-06** Backspace to empty returns deterministically to idle.

## 6. Install and uninstall safety

- **AT-WIN-01** The reserved experimental CLSID/profile GUID differ from known
  official Weasel identifiers present in the integration fixture.
- **AT-WIN-02** Install planning and execution accept only the experimental
  pair and display name.
- **AT-WIN-03** Installation never requests default-profile activation.
- **AT-WIN-04** Uninstall planning/execution refuse a non-experimental CLSID or
  profile GUID.
- **AT-WIN-05** Install and uninstall scripts contain fail-closed identifier
  checks and touch only the isolated development directory/profile.
- **AT-WIN-06** Missing model service does not crash the native query boundary.
- **AT-WIN-07** On a Windows test user/VM, the profile can be installed,
  manually selected, used for a Chinese and English smoke input, uninstalled,
  and leaves the pre-existing Weasel/Microsoft Pinyin profile list unchanged.

`AT-WIN-07` cannot pass on a non-Windows host. CI or a recorded user-machine run
must supply the evidence.

## 7. Replay benchmark

The checked-in replay fixture contains:

- an English theoretical-physics paragraph;
- a Chinese technical discussion;
- mixed Chinese/English text;
- model names and acronyms;
- a rapid-key sequence with intentionally stale snapshots.

The benchmark emits:

```text
top_1_accuracy
top_5_recall
literal_fallback_rate
wrong_script_candidate_count
snapshot_age_ms_at_query
candidate_query_ms_p50
candidate_query_ms_p95
candidate_query_ms_p99
model_refresh_ms_p50
model_refresh_ms_p95
```

- **AT-RP-01** Output contains every required metric and case count.
- **AT-RP-02** English-context replay reports zero Han candidates.
- **AT-RP-03** Chinese-context replay can surface `Qwen`, `Qwen3.5`, and fixture
  acronyms.
- **AT-RP-04** Replay reports quality differences attributable to old snapshots;
  it does not fail solely because refresh p95 exceeds 100 ms.
- **AT-RP-05** Percentiles are calculated from measured durations, never fixed
  constants.

## 8. Release evidence

Before the draft PR:

1. inspect the complete diff against `main`;
2. run all Python tests;
3. run focused bilingual/backend/state-machine/replay tests;
4. run lint and format checks;
5. build and run native tests on Windows;
6. install/smoke/uninstall in a safe Windows environment;
7. record real performance data only where the required hardware is present;
8. update `README.md` and `docs/STATUS.md`.

Any step not executable in the current environment remains explicitly
unverified and blocks a claim of a fully install-tested deliverable, but it does
not justify inventing a passing result.
