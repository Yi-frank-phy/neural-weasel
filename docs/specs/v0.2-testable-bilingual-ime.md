# v0.2 testable unified bilingual IME specification

Status: implementation contract for `feat/testable-unified-bilingual-ime`.

The v0.2 goal is an experimental Windows profile that can be installed beside
Microsoft Pinyin and an existing Weasel installation, switched to manually, and
used for real Chinese and English typing. It is not production ready.

## 1. Terms and observable state

- **raw keys**: the uncommitted ASCII key sequence typed by the user.
- **literal prefix**: `raw_keys` preserved byte-for-byte for direct commit.
- **context**: bounded text before and after the caret.
- **context epoch**: monotonically increasing identifier assigned when a context
  update is requested.
- **snapshot**: immutable model continuation state published for one context
  epoch.
- **stable script state**: the last decisive `chinese` or `english` context
  classification in the current non-private session.
- **key path**: TSF/Rime handling from a key event until it returns to the
  editor.
- **model path**: model loading, `forward`, context cache update, and snapshot
  publication in the separate model service.

The engine exposes these states:

```text
service = preparing | ready | unavailable
composition = idle | composing
script_policy = chinese | english | ambiguous
snapshot = absent | immutable(epoch, created_monotonic, backend_kind)
completion = none | offered | explicitly_selected
```

## 2. Unified candidate contract

`Candidate` is shared by pinyin and Latin-prefix constraints. It contains at
least:

```text
text: str
consumed_keys: int
constraint_kind: pinyin | latin_prefix | literal
script: han | latin | mixed | other
model_score: float | None
constraint_cost: float
language_prior: float
total_score: float
context_epoch: int
token_path: tuple[int, ...]
```

Compatibility fields used by the v0.1 protocol may remain during migration.
Chinese and English candidates pass through one deterministic pipeline:

1. validate candidate and epoch;
2. apply the context script policy;
3. combine the sequence model score, constraint cost, and language prior;
4. de-duplicate by Unicode-normalized display text;
5. sort by `total_score`, then deterministic tie breakers;
6. publish at most `top_k` candidates with the snapshot epoch.

There must not be separate Chinese and English rankers.

## 3. Model backend contract

`ModelBackend` is the smallest shared boundary needed by the engine:

```text
load()
update_context(before, after) -> immutable BackendState
latest_state() -> BackendState | None
score_allowed_tokens(state, allowed_token_ids) -> scores
diagnostics() -> mapping
invalidate_private_state()
```

Names may differ, but responsibilities may not be folded back into one
Qwen-specific engine class. `update_context` is the only operation allowed to
perform a model forward. It is called only by the model-service context worker.

### MB-01 FullLogitsSnapshotBackend

The correctness baseline performs:

```text
forward -> full vocabulary logits -> immutable CPU float32 vector
```

Allowed-token scoring indexes the immutable vector and performs no model or GPU
work.

### MB-02 SparseProjectionBackend

The experimental backend performs:

```text
base-model forward -> immutable last hidden continuation state
allowed token ids -> selected lm_head rows -> bounded matrix product -> scores
```

It may use existing PyTorch indexing and matrix multiplication. It must not use
custom CUDA, Triton, an Instruct model, or a chat prompt. Projection may run in
the model service's bounded query work; it must never call `model.forward`.

For the same model weights, context, and allowed token ids, sparse and full
backends must have:

- identical top-1 token;
- identical top-k token set after deterministic tie handling;
- score differences at most `1e-4` in float32 reference tests and at most
  `2e-2` for BF16 GPU measurements.

Diagnostics report backend kind, state epoch, snapshot publication latency,
snapshot age, peak allocated GPU bytes where available, and projection/query
latency.

## 4. Snapshot and key-path invariants

- **RT-01** No key-path code calls `model.forward` or `update_context`.
- **RT-02** A key query reads one already-published immutable snapshot.
- **RT-03** A key query never waits for a newer epoch.
- **RT-04** If a newer snapshot is not ready, the latest older snapshot remains
  queryable.
- **RT-05** A result for epoch `n` cannot overwrite an already requested or
  published epoch greater than `n`.
- **RT-06** Snapshot age is diagnostic data, not a release rejection by itself.
- **RT-07** Service absence, timeout, malformed response, or epoch mismatch
  returns no AI replacement within the configured native deadline. The literal
  composition remains recoverable.
- **RT-08** Entering a protected field invalidates all snapshots and cached
  private continuation state.

Cold start and first snapshot may be slow. The UI may expose a non-blocking
`模型正在准备` status, but no editor may wait for model loading.

## 5. Context script policy

Only Han and Latin letters in the last 128 Unicode code points before the caret
participate in the decisive statistic. Digits, punctuation, whitespace, and
mathematical symbols are neutral.

- `english`: at least 8 Latin letters and Latin letters are at least 70% of
  counted Han plus Latin characters.
- `chinese`: at least 2 Han characters and Han characters are at least 30% of
  counted Han plus Latin characters.
- `ambiguous`: neither rule is decisive.

If both rules are true, the script of the nearest run of at least two letters or
Han characters wins. If no such run exists, use `ambiguous`.

For `ambiguous`, the stable script state supplies a weak prior. If there is no
stable state, Chinese is the deterministic weak default. A committed
non-literal candidate or an unambiguously scripted literal commit updates the
stable state. Model support may affect ranking inside the allowed set, but may
not override a hard script prohibition.

### SP-01 English context

- Han or Han-dominant mixed candidates are hard rejected.
- Latin candidates are allowed with no script penalty.
- Literal Latin input is always commit-able.

### SP-02 Chinese context

- Han candidates are allowed.
- Latin candidates are allowed with a fixed, configurable default prior penalty
  of `-0.35`.
- The Latin penalty is reduced to zero for an explicit Latin prefix with an
  uppercase pattern, acronym shape, or a non-pinyin Latin structure.
- Ranking does not compute a cross-candidate model margin to change this prior.
- There is no proper-name whitelist.

### SP-03 Ambiguous context

Both scripts remain allowed. The stable/default script receives a `0.15` weak
prior advantage. No script is hard rejected.

## 6. Constraints

### CN-01 PinyinConstraint

The v0.1 continuous full-pinyin legality rules remain the Chinese constraint
baseline. For v0.2, fuzzy pinyin, double pinyin, abbreviations, tones, and typo
correction remain out of scope.

### EN-01 LatinPrefixConstraint

Given a literal prefix, candidates are Base-model causal continuations that
start with that prefix under Unicode case-insensitive comparison while
preserving the candidate's model spelling.

The bounded search supports:

- one-token and multi-token words;
- ASCII case variants;
- internal hyphen and apostrophe;
- deletion and retyping because queries are stateless in `raw_keys`;
- a literal fallback candidate for every non-empty valid Latin prefix.

Search bounds are deterministic: at most 4 continuation tokens, 48 display
characters, beam width 32, and 128 scored token expansions per depth. A
candidate ends at whitespace, terminal punctuation, or the bounds. Search never
crosses into Han text.

Sequence score is:

```text
normalized_model_score =
    sum(log_probability(token_i)) / token_count ** 0.7

total_score =
    normalized_model_score + language_prior + constraint_cost
```

`constraint_cost` is zero for a complete compatible word and `-0.1` for a
truncated-at-bound candidate. The literal fallback has no fabricated
`model_score`; it sorts after valid model candidates unless explicitly selected
or the policy rejects every model candidate.

## 7. Key interaction state machine

### KS-01 Chinese/pinyin composition

- `Space`: commit the selected Chinese candidate.
- `1..9`: commit the numbered candidate.
- `Enter`: commit the literal composition.
- `Escape`: cancel the composition without inserting a model replacement.

### KS-02 English composition

- Character/backspace: update the literal prefix and the completion offer.
- `Space`: commit the literal prefix exactly, then insert one space.
- `Tab`: commit the selected AI completion; if none is valid, leave the literal
  prefix unchanged.
- `1..9` or arrows plus an explicit accept action: select another completion.
- `Escape`: dismiss completion and preserve the literal prefix; it must not
  replace the prefix with model text.
- `Enter`: commit the literal prefix and the editor's normal Enter behavior.

English `Space` never silently substitutes the top model completion.

## 8. Windows experimental profile

The profile display name is `神经小狼毫（实验）`. It uses only the reserved
experimental CLSID and zh-CN profile GUID in
`native/tsf/experimental_profile_ids.h`.

- Installation is explicit, per experimental build, and idempotent.
- Installation does not set the profile as default or disable another profile.
- Uninstallation refuses identifiers other than the two reserved experimental
  identifiers.
- Official Weasel and Microsoft Pinyin identifiers are never targets.
- A missing model service yields literal/cancel behavior rather than a process
  crash.
- Native pipe work has an absolute bounded deadline and no model forward.
- Smoke installation occurs only in an explicit test user/VM unless the user
  knowingly runs the development script.

Required scripts:

```text
scripts/install-dev-profile.ps1
scripts/uninstall-dev-profile.ps1
scripts/start-model-service.ps1
scripts/diagnose.ps1
```

If the repository cannot safely build a full Weasel fork in this iteration, the
deliverable may be an isolated development build plus exact manual integration
steps. A profile-plan-only scaffold does not satisfy this requirement.

## 9. Errors and degradation

| Condition | Required behavior |
| --- | --- |
| Model loading | Report preparing; literal input remains available |
| No snapshot | Return literal fallback only |
| Stale snapshot | Query it, record age and epoch |
| Newer epoch in flight | Never wait; keep current immutable snapshot |
| Pipe unavailable/timeout | Return safely before deadline; no AI substitution |
| Malformed/stale response | Discard response |
| Sparse backend unsupported | Select full-logits backend explicitly and diagnose reason |
| Protected field | Clear snapshots/cache and emit no private text |
| Install identifier conflict | Stop without changing any profile |
| Uninstall identifier mismatch | Refuse the operation |

## 10. Explicit non-goals

Android, iPadOS, cloud inference, model routing, long-term personalization,
complex dictionary fusion, fuzzy pinyin, double pinyin, a large GUI, automatic
updates, custom kernels, a formal 9B migration, automatic Microsoft Pinyin
activation, and a complex prediction tree are not part of v0.2.

## 11. Known uncertainties

- Real Qwen3.5 sparse/full speed and memory differences require the user's RTX
  4060 Laptop GPU; CPU synthetic timings are not substitutes.
- The exact Weasel fork/build revision and signing policy available on the
  Windows test machine remain external inputs.
- Some editors handle `Tab` before TSF composition; the native integration must
  record editor-specific smoke results rather than claiming universal capture.
- Base-model vocabulary search may not surface every dictionary-valid English
  completion within the fixed bounds. Literal fallback is therefore mandatory.
